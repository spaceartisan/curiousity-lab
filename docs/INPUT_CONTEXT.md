# Local game input observations

Optional activity history records only categories of input observed inside visible, unpaused game controls: `keyboard`, `mouse`, `pen`, `touch`. This is not a device inventory, fingerprint, accessibility-tool detector or a count of actions. No raw DOM event, pressed key, typed text, coordinate or gesture stream is stored. A category does not prove that an answer was submitted or identify which person interacted.

Presentation metadata has optional `input: {version: 1, coverage: from-start | partial, methods: []}`. Fresh attempts initialize empty capture from start. Old/resumed attempts and enabling history during a puzzle initialize partial capture; imported immutable source sessions retain exactly their original fields. An absent field means unrecorded, while an empty list means no supported category has yet been observed during this capture window. Partial capture never becomes complete just because more inputs arrive. Sorted unique sets have at most four entries; invalid or private payload properties are rejected on import/preparation.

Only pointer-down categories and keyboard interaction within the game surface are eligible. Header navigation, Settings, home screens, pause/resume panels, creations and Insights are outside this boundary. Pure modifier keys, Escape and browser shortcut combinations are ignored. No attempt is made to infer input from screen size, clicks with unspecified pointer type, focus, programmatic changes or presence of a touchscreen. Browser/assistive technology may expose categories differently; unrecognized inputs remain unknown. Tab navigation within controls can record keyboard. This observation is not a normalized action event or a measure of motor ability.

Capture occurs before the selected control action. A control that replaces content or changes mode belongs to the outgoing attempt; its method is not falsely inherited by the new attempt. The final move can be included before filing. Filed sessions cannot be modified by later interactions or view changes. Replays create a fresh capture window; offline resume retains the original one. Repeated use of an already observed category does not create more storage writes for this metadata.

History-off does not collect categories. Disabling history removes optional draft metadata under the existing consent reset behavior; existing filed history is retained until explicitly cleared. Clear-history removes presentation/input observations from current drafts and durable undo copies while preserving necessary puzzle progress. JSON backups and exact presentation JSON in CSV retain source categories. Local Insights sharing preparation validates the same allowlist; Companion preparation still receives only coarse game/outcome/end fields. No upload or security-rule change exists.

`local-context-review-5` and `local-session-points-3` distinguish coverage and canonical input sets along with previous task/presentation/timing context. This additional grouping dimension is explicit algorithm versioning; old source records are never rewritten. Grouping does not establish comparable difficulty, independent participants, diagnosis or causation. Installation provenance, timezone/clock quality, normalized task revisions, private family sync and production recovery remain unfinished.
